# Phase 3 — Plan

**Objective:** Dispatch the `planner` agent to produce `builds/<slug>/plan.json`, validate it against the schema, render a readable summary, and get user approval before building.

**Prerequisite:** `builds/<slug>/requirements.md` and `builds/<slug>/research.md` both exist.

---

## Procedure

### Step 1 — Dispatch `planner`

Dispatch the `planner` agent via the Agent tool:

```
Prompt: "Read builds/<slug>/requirements.md and builds/<slug>/research.md, then produce a
plan.json for slug=<slug>. Return the full JSON object as your response — do not attempt to
write any file; you have read-only tools. Validate your output mentally against
skills/airo-architect/references/plan-schema.json before returning."

agentType: "planner"
```

The `planner` runs on `model: sonnet` (its frontmatter), honored automatically on the Agent tool path. The planner **returns** the plan JSON as its output — it does not and cannot write files (it only has `Read` tools). Writing the file is the orchestrator's job (Step 2 below).

### Step 2 — Write `plan.json`

The **orchestrator** (you) owns this write. Take the JSON object the planner returned in Step 1 and write it to `builds/<slug>/plan.json` yourself. Do not assume the planner has written anything — confirm the file exists and is non-empty only because you just created it.

### Step 3 — Validate against the schema

Run the following validation check, setting `SLUG` to the real slug as a shell variable so there is no manual placeholder substitution to forget:

```bash
SLUG=it-support
python3 -c "
import json, jsonschema, pathlib
schema = json.loads(pathlib.Path('skills/airo-architect/references/plan-schema.json').read_text())
plan   = json.loads(pathlib.Path(f'builds/{SLUG}/plan.json').read_text())
jsonschema.validate(plan, schema)
print('valid')
"
```

If validation fails, read the error, identify which field is missing or invalid, and re-run the planner with a corrective note. Do not present an invalid plan for review.

### Step 4 — Render a readable summary

Do not show the user raw JSON. Instead, render a structured summary grouped by the plan's makeup sections. Use this template (omit sections not present in the plan):

---

**Plan: `<slug>` (`<target>`)**

**Summary:** `<plan.summary>`

**Connections** (`<count>`)
| Name | App | Status |
|------|-----|--------|
| ... | ... | exists / create |

**Skills** (`<count>`) — genie target only
- **`<name>`** — `<description>` · Input: `<io_contract.input>` → Output: `<io_contract.output>`

**Knowledge Bases** (`<count>`) — genie target only
- **`<name>`** — sources: `<type>:<ref>`, ...

**Interfaces** — genie target only
- `<name>` (`<role>`)

**Recipe Blueprint** — recipe target only
- Trigger: `<app>` / `<event>`
- Steps: `<app>.<action>` [notes] · ...

**Data Tables** (`<count>`)
- **`<name>`** (`<purpose>`) — columns: `<col>:<type>`, ...

**Tests** (`<count>`)
| Name | Input | Expected | Grades on |
|------|-------|----------|-----------|
| ... | ... | ... | ... |

---

In addition to the table above, render a diagram via the visualize widget (`mcp__visualize__show_widget`) **by default** at plan review — do not wait for the user to ask for a visual; this is the default Tier-2 review artifact. The diagram must:

- Color-code AND text-label every node by asset type (Genie / Recipe / Data Table / External), so the type is legible even without color.
- Draw edges for both data flow and dependency between assets.
- Be generated by iterating the plan's assets and `recipe_blueprint.steps` directly — not from a paraphrase or summary of the plan — so that no step is silently dropped.
- Render any `ai_generation` step in a distinct highlight (it is usually the core value of the solution and must stand out from plain data-fetch/action steps).

### Step 5 — Default review

After presenting the summary, ask:

> "Approve this makeup before I build?"

**On approval:** proceed to Phase 4.

**On rejection or change request:** capture the user's corrections, describe them to the planner in a follow-up Agent call:

```
Prompt: "The user rejected the plan for builds/<slug>. Their corrections: <corrections>.
Re-read builds/<slug>/requirements.md and builds/<slug>/research.md, apply the corrections,
and produce a revised plan.json. Return the full JSON — do not attempt to write any file."

agentType: "planner"
```

The planner again only returns JSON. You (the orchestrator) overwrite `builds/<slug>/plan.json` with the revised output, re-validate, re-render (including the diagram), and ask for approval again. Repeat until approved.

---

## Notes

- The validation step is non-optional. A plan that fails schema validation will cause the builder to fail in Phase 4, wasting sandbox provisioning time.
- The readable summary is the user's primary tool for catching mistakes (wrong connections, missing KBs, wrong test cases). Make it scannable — tables over prose for structured data.
- The plan diagram (Step 4) is not optional polish — it is the default Tier-2 review artifact alongside the table. Build it from the plan's actual asset list and `recipe_blueprint.steps`, not a mental summary, so every step shows up and `ai_generation` steps are visually distinct.
- The planner never writes `builds/<slug>/plan.json` itself — its tools are read-only. The orchestrator writes the file every time (initial plan and every revision) before validating.
- If the planner produces a plan with `status: "create"` connections that already appeared in the platform inventory as existing, flag this as a likely planner error and ask the planner to revise before showing the summary to the user.
- The schema file is at `skills/airo-architect/references/plan-schema.json`. Required top-level fields for all targets: `target`, `slug`, `summary`, `connections`, `tests`. Additional required field for `target: recipe`: `recipe_blueprint`. For `target: genie`, `skills`, `knowledge_bases`, and `interfaces` should be present (not schema-required but practically required for a buildable genie).
